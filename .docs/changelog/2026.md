## [2026-08-04] — Despliegue en producción (Vercel + Render + Neon + Upstash) / ADR-010

**Tipo:** DECISIÓN + INFRAESTRUCTURA
**Área:** decisions/ | architecture/
**Archivos afectados:**
- `.docs/decisions/ADR-010-arquitectura-de-despliegue.md` (CREACIÓN)
- `.docs/architecture/deployment.md` (CREACIÓN)
- `render.yaml` (CREACIÓN — Blueprint de Render)
- `frontend/vercel.json` (CREACIÓN — config de Vercel)

**Descripción:**
Se desplegó TrimFlow en producción con servicios independientes por capa: frontend en **Vercel** (`frontend/`), backend en **Render** (`backend/`, build nativo de Node 20), base de datos en **Neon** y Redis en **Upstash**. Se corrigieron problemas de deploy: `nest: not found` (Render omite devDependencies → `npm ci --include=dev`), migraciones que no se ejecutaban (`migrationsRun: true` en TypeOrmModule) y seed que no poblaba la base (seed automático si `users` está vacía). El prefijo de API es `/v1`.

**Motivación:**
Poner el stack completo en producción y documentar la arquitectura de despliegue para reproducibilidad.

## [2026-08-02] — Riesgo aceptado de dependencias transitivas (postcss + sharp) / ADR-009

**Tipo:** DECISIÓN
**Área:** decisions/ | reports/
**Archivos afectados:**
- `.docs/decisions/ADR-009-gestion-de-riesgo-dependencias-transitivas.md` (CREACIÓN)
- `reports/2026-08-02-frontend-audit.md` (CREACIÓN)

**Descripción:**
`npm audit` reportaba 4 vulnerabilidades high en el frontend. `npm audit fix` (sin `--force`) resolvió `brace-expansion` (1 de 4). Las 3 restantes (`postcss` y `sharp`, transitivas de `next`) quedaron documentadas como **riesgo aceptado** en el ADR-009. Se descartó `npm audit fix --force` (instalaría next@9.3.3, downgrade breaking) y se decidió NO actualizar Next.js (el rango vulnerable incluye la última estable 16.2.12). Criterio de cierre: cuando exista `next` estable > 16.3.0-preview.7 sin las dependencias vulnerables.

**Motivación:**
Resolver las observaciones BAJA del sprint de testing del frontend manteniendo `test`, `lint` y `build` verdes y sin introducir breaking changes.

## [2026-08-01] — ADR-007: rediseño de UI de dashboards (inspirado en Admindek Next)

**Tipo:** CREACIÓN / MODIFICACIÓN
**Área:** decisions/ | PROJECT.md
**Archivos afectados:**
- `.docs/decisions/ADR-007-rediseno-ui-dashboards.md` (CREACIÓN)
- `.docs/PROJECT.md` (MODIFICACIÓN: tabla de stack frontend)

**Descripción:**
Se documentó la adopción del rediseño de UI "inspirado en Admindek Next" para los 3 dashboards (admin, barber, super-admin). El ADR-007 fija la paleta ocean-blue (#4680ff) y tokens del template aplicados a shadcn/ui, dark mode con toggle vía next-themes, y la incorporación de recharts como nueva dependencia para los charts (con restricción de licencia: réplica inspirada, componentes propios desde cero). Además se corrigió la tabla de stack del frontend en PROJECT.md a las versiones reales (Next.js 16.2.x, React 19.x, Tailwind CSS 4.x, lucide-react) y se añadió recharts como dependencia prevista.

**Motivación:**
El stack real del frontend (verificado en frontend/package.json) estaba desactualizado en PROJECT.md (declaraba React 18.x y Tailwind 3.x), y faltaban ADRs sobre decisiones de UI. Se requiere una fuente de verdad para el objetivo de rediseño de dashboards, incluyendo tokens de tema, dark mode, charts y el límite de licencia.
